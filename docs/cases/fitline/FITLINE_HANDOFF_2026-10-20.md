# FitLine / PM-International — точка остановки

Владелец 20.10.2026 выбрал другой бизнес для следующих испытаний HARNES и поручил сохранить возможность вернуться к FitLine. Новый бизнес ещё не описан. Этот checkpoint не означает отказ от HARNES или доказанный провал FitLine на всём рынке.

## Как продолжить через несколько месяцев

1. Прочитать этот документ и независимый аудит исследования в этой папке.
2. Найти локальный checkpoint `D:/HARNES2-backups/fitline-2026-10-20/`. Проверить `ARCHIVE_RECEIPT.json`, расшифровать и восстановить архив только в НОВУЮ папку посредством `restore_private.py`. Обычный запуск: `python restore_private.py D:/HARNES2-fitline-restore-NEW`. Нужен установленный пакет `cryptography` и исходная Windows-учётная запись с рабочим DPAPI-профилем.
3. Проверить `MANIFEST.json`: он сопоставляет архивные файлы исходным путям, содержит SHA-256, Git/worktree references, сведения о SQLite backup, исключениях и исторических повреждённых тестовых фикстурах. Не объявлять все тестовые БД здоровыми.
4. Использовать сохранённый `repository.bundle` для локального чтения старых branches/code. Пример: `git clone repository.bundle D:/HARNES2-fitline-code-NEW`. Восстановленные изменения рабочих папок применять только после просмотра отдельных patches; не применять их поверх будущего main автоматически.
5. Начать с ПОСЛЕ-паузы snapshot shared Store; `pre-pause/` нужен для расследования прежнего состояния. Не копировать старую БД поверх нового бизнеса. Не запускать сохранённые one-shot/spent drivers и launchers; они являются доказательствами прошлых запусков.
6. Определить актуальные страну, предложение, источники и цель. Проверить свежесть источников и условий PM. Выдать новые конечные grants штатными командами. Старые approvals/grants/sessions/history не считать разрешением на новый запуск.
7. Выбрать один проверяемый эксперимент из раздела «Незаконченная работа». Старые отрицательные выборки не пересчитывать ради получения положительного вывода.

Важное ограничение хранения: шифрование AES-256-GCM, ключ защищён Windows DPAPI CurrentUser; NTFS-доступ ограничен текущим пользователем и SYSTEM. Это локальная копия на том же диске, а не независимый off-site disaster recovery. Потеря диска или исходного Windows-профиля может сделать приватный архив недоступным. Исходные рабочие файлы также оставлены на своих местах. GitHub хранит безопасную документацию и код, но не приватный архив.

Credential/session-файлы и browser profiles исключены из копирования по пути. Авторизация остаётся в исходных системах. В исторических logs/config/code могут быть чувствительные данные: весь приватный payload считается закрытым, даже если отдельный источник был публичным. Не публиковать его целиком.

## Исходная идея и выбранная позиция

Постоянный открыто обозначенный AI-партнёр наблюдает за разрешёнными источниками, помнит важное, предлагает следующий ход, проверяет результат и корректирует план. Он может аргументированно спорить с владельцем. Пользовательский результат оценивается по понятным карточкам с источником, гипотезой, неопределённостью и предложенным шагом.

Владелец пока не вступил в PM-International. У команды не подтверждены условия поддержки новичка, расходы и бонусная квалификация для выбранного рынка. Возможная будущая продажа HARNES компании — намерение владельца, не договорённость с PM.

Позиция владельца: прозрачная AI-идентичность, честное обозначение коммерческой модели, отсутствие поддельных людей и инсценированного спроса. Найденный источник, интерес человека, коммерческая совместимость и разрешение на контакт — разные вещи.

## Незаконченная работа

1. **Выраженный спрос и гипотеза совместимости.** `business/opportunity-projection.mjs` требует собственной потребности/вопроса/намерения; seller promotions не считаются положительным targeting evidence. Поэтому подать рекламную страницу этому prompt и получить null — не доказательство слабости модели. Отдельная compatibility hypothesis не реализована и не проверена. Если вернуться к ней, сначала установить конкретную возможную выгоду предложения и контрпримеры, затем выбрать минимальный конечный запуск. NO BASIS — допустимый правильный результат.
2. **Польза предложения.** Разделять покупателя продукта, человека, ищущего заработок на продаже, и клиента AI-помощника. По конкретной стране проверить официальные расходы, закупки, доставку, бонусные условия и альтернативы. Не обещать превосходство продукта, медицинский эффект или доход.
3. **Опыт.** Сохранение урока и prompted replay проверены. Автоматическая применимость reviewed lessons к Scout/Opportunity с freshness/provenance ещё не доказана. Не объявлять это готовым самообучением.
4. **Следующий тест.** Ограниченное чтение реальных самостоятельных деловых вопросов и показ нескольких обоснованных карточек владельцу. В подготовленных research briefs есть границы. Возвращение к кейсу не требует сначала строить новый parser/runtime/framework.
