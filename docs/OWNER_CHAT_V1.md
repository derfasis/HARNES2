# Чат владельца с партнёром

Решение владельца от 25 ноября 2026: использовать Hermes целиком, а не строить рядом свой. Владелец
говорит с партнёром в Telegram через **родной шлюз Hermes**; долгую память разговоров держит
**Hindsight**, подключённый штатным модулем Hermes. Прежний самодельный мост (`PARTNER_OWNER_BOT_TOKEN`
→ заметка в тетради → ответ) удалён.

## Что здесь чужое и что наше

| Часть | Чьё | Где |
| --- | --- | --- |
| Разговор, сессии, команды, доставка в Telegram | Hermes (шлюз) | `runtime/hermes-agent`, дом `data/hermes-gateway/` |
| Долгая память разговоров | Hindsight 1.2.1, отдельный локальный сервер | `data/hindsight/venv`, `127.0.0.1:8890` |
| Инструменты стола в чате | существующий MCP-адаптер | `adapters/mcp/server.py` |
| Один ход чата = один запуск партнёра | наше | `business/owner-chat.mjs` |
| Тетрадь перед глазами и границы хода | наше, плагин Hermes на 90 строк | `adapters/hermes/owner_gateway/partner_desk/` |
| Подготовка дома и запуск | наше | `adapters/hermes/owner_gateway/setup.py`, `launch.py`, `scripts/partner-chat.ps1` |

Наш код не хранит переписку, не выбирает ответ и ничего не отправляет.

## Как проходит один ход

1. Владелец пишет боту. Hermes принимает сообщение только от разрешённого Telegram-id.
2. Плагин `partner-desk` (хук `pre_llm_call`) открывает ход: `POST /internal/chat/turn {op: begin}`.
   Сервис возвращает тетрадь партнёра и обстановку за столом. Плагин кладёт их в сообщение, только
   если этого текста ещё нет в разговоре: в начале сессии, после изменения и после сжатия истории.
3. Модель отвечает. Читать стол (`partner_get_context`, `partner_list_work`,
   `partner_search_experience`) можно без запуска.
4. Первая **запись** за ход — в тетрадь или своя задача — допускается как запуск партнёра
   (`runs.runtime = 'owner-chat'`) с билетом control plane на плоскости `private`. Остальные записи
   хода идут в тот же запуск. Дальше действуют те же проверки, что за столом: стоп-лист, дневной
   лимит своих задач, правила тетради.
5. После ответа плагин закрывает ход (`post_llm_call` → `op: end`): запуск завершён, билет отпущен.

Следствия:

- Ход, в котором партнёр только разговаривает, не создаёт ни запуска, ни билета.
- Итог по записи журнала нельзя записать в том же ходе, где она открыта. Слова владельца о результате
  приходят новым сообщением, то есть новым ходом и новым запуском.
- Стол и чат делят плоскость `private` по очереди. Если идёт рабочий запуск, запись из чата ждёт до
  45 секунд и затем честно отказывает; пока чат пишет, стол получает `CONTROL_CAPACITY` и приходит позже.
- Брошенный ход (шлюз упал, ответ прерван) закрывается сам: следующим сообщением, по времени или при
  остановке сервиса. Запуск помечается `interrupted`; уже сделанные записи остаются.
- Стоимость хода сервису неизвестна: вызов модели делает шлюз. Запуск помечен `cost_status =
  'external'`: он не показывается как известный ноль и не останавливает стол как «неоплаченный счёт».

## Что партнёр может из чата

- Читать: материалы предложения, контакты, уроки, задачи, свою тетрадь.
- Писать в свою тетрадь: ожидание, итог, правило, стоп, прочитанное, ответ на заметку владельца.
- Ставить себе работу за стол: `research`, `planning`, `review` — в пределах `autonomy.maxOwnTasksPerDay`.
- Помнить разговоры: встроенные заметки Hermes и Hindsight.
- Пользоваться своим браузером и своим кабинетом YOVI (см. «Браузер партнёра»).

Чего не может: писать людям через рабочий аккаунт, готовить черновики, запускать команды и читать
файлы (терминал, файлы, код, cron и делегирование в шлюзе выключены). Первым он пока не пишет.

## Браузер партнёра

Решение владельца от 25 ноября 2026: у партнёра свой браузер с полным доступом и свой аккаунт YOVI,
без технических замков. Это родной набор инструментов `browser` Hermes. Он подключается к отдельному
окну Chrome с собственным профилем (`data/partner-browser/profile`, порт отладки `127.0.0.1:9222`),
которое открывает `scripts/partner-chat.ps1` (при запуске чата или `-Action Browser`). Владелец входит
в кабинет в этом окне сам; пароль и коды партнёру не передаются. Профили владельца и других
инструментов не используются.

Что из этого следует, прямо:

- Кода, который помешал бы партнёру нажать в кабинете то, что стоит денег, нет. Остаётся его
  собственное правило из `partner/identity.md`: деньги без владельца он не тратит.
- Списка разрешённых сайтов нет: браузером он может открыть любой адрес.
- Всё, что он читает в браузере, уходит модели и в память чата.
- Окном с открытой сессией может управлять любая программа на этой машине: порт отладки Chrome
  слушает только `127.0.0.1`, но пароля у него нет.

## Установка и запуск

В `.env` проекта:

```
PARTNER_OWNER_BOT_TOKEN=<токен бота от @BotFather>
PARTNER_OWNER_TELEGRAM_ID=<числовой Telegram-id владельца>
```

```powershell
npm run chat:setup    # дом Hermes, плагин, клиент Hindsight, сервер Hindsight и его профиль
npm run chat:start    # или START-PARTNER-CHAT.bat: прокси, память, шлюз
npm run chat:status
npm run chat:stop     # или STOP-PARTNER-CHAT.bat
```

Сервис партнёра (`START-PARTNER.bat`) должен работать: без него чат отвечает, но не видит ни тетрадь,
ни задачи, и прямо говорит об этом. Повторный `chat:setup` безопасен: значения, которые владелец уже
задал в `data/hermes-gateway/.env` и `config.yaml`, сохраняются; существующий профиль Hindsight не
трогается. Секреты лежат только в `.env`-файлах; в `config.yaml` стоит ссылка `${PARTNER_MODEL_API_KEY}`.

Где что лежит:

- `data/hermes-gateway/` — дом Hermes: настройки, сессии, журналы, встроенные заметки.
- `%USERPROFILE%/.hindsight/profiles/harnes2.env` — настройки сервера памяти.
- `%USERPROFILE%/.pg0/instances/hindsight-embed-harnes2` — сама память. Она вне папки проекта и в
  экспорт проекта не входит.

## Принятые решения и ограничения

- **Hindsight стоит отдельно, не внутри `.venv`.** `uv pip install hindsight-all` в окружение Hermes
  заменил бы десять закреплённых пакетов, на которых работает партнёр (mcp, httpx2, anyio и другие).
  Сервер живёт в `data/hindsight/venv`, Hermes подключён в своём режиме «local external» с клиентом,
  который закрепляет сам (`hindsight-client==0.6.1`, ставится установщиком Hermes в
  `data/hermes-gateway/packages`).
- **Версия 1.2.1, а не последняя.** Выпуски моложе недели не ставятся; зависимости ограничены датой
  2026-11-18 (`--exclude-newer`).
- **Русский язык.** Многоязычные эмбеддинги (ONNX, `multilingual-e5-small`) и русский словарь
  полнотекстового поиска. Модель извлечения — `gemini-3-flash` через тот же локальный прокси, не больше
  двух вызовов одновременно.
- **Настройки агента те же, что у рабочих запусков** (`adapters/hermes/runner.py`): блоки Hermes для
  агента-программиста выключены, блок о машине не отправляется. С блоками по умолчанию («Finishing the
  job», «Google model operational directives») маршрут модели отвечал HTTP 429 на каждый запрос; с этими
  настройками принимает. Почему — не установлено. Больше в запросах ничего не меняется.
- **Память сервера — около 2 ГБ ОЗУ.** На каждое сообщение уходит несколько дополнительных вызовов
  `gemini-3-flash` на запись в память.
- **Материалы YOVI живут семь дней.** Когда срок выходит, партнёр видит это в обстановке и просит у
  владельца актуальные; условий по памяти он не называет.
- **Остановка шлюза — завершение процесса.** Мягче на Windows не умеет и сам `hermes gateway stop`.
