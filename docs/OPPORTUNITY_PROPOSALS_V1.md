# Opportunity Proposals v1

Canonical starting point: `main@e4c704071a2290ead118d5127c35958711539e31`.
Branch: `codex/opportunity-proposals-v1`. The existing read-only pilot continues in its own worktree; primary workspace changes are preserved.

## Why this layer

The actual Gemini pilot produced a specific, unverified volunteer-timekeeper lead. The same saved packet contained a separate volunteer-roster update, which the proposal did not discuss. That update does not prove the timekeeper role was filled. Source publication/edit times exist in canonical ingest but were omitted from the model evidence envelope: observation time was described as publication time. There is also no material to inspect before accepting the hypothesis.

The next useful product result is one inspectable proposal containing the source statement, the other supplied context, uncertainty, distinct clocks, and a ready text preview. It must preserve existing owner reviews instead of treating a model recommendation as authority.

## Architecture and boundaries

- Reuse canonical ingest, Audience exchange projection/fairness, AJV, Hermes no-tool reasoning, existing versioned JSON records, Continuity, Work Core, and Action. No new transport/parser, queue, storage engine, or workflow engine is needed.
- Add `published_at` and `source_updated_at` to evidence beside `observed_at` and Browser `confirmed_at`. Missing source dates remain null. This does not change source freshness/expiry semantics or fabricate publication recency from intake.
- New model proposals use version 2. Each proposed need classifies every exchange in the supplied bounded packet as supporting, related, counterevidence, uncertain, or unrelated, with exact exchange/event references and a reason. This proves bounded context accounting, not semantic truth or source completeness.
- `context_event_ids` are separate from support and counterevidence. Selected related/uncertain context is part of the durable need basis and future Work scope. Unrelated exchanges are disclosed but are not permanent dependencies. No entire-source/same-author poisoning.
- Version 2 `prepare_material` includes a bounded inert `material_preview` (title, exact Markdown content, citation IDs). It cannot name a recipient, grant permissions, create a person/conversation/business draft, or execute a capability. The service computes its SHA256 and `preview_basis_event_ids` from ALL selected support/counter/context dependencies; model citations cannot narrow that basis. Import uses that full server-owned basis. Model output cannot provide authority or a trusted digest.
- Historical version 1 proposals remain visible as having no recorded context review/preview. New model assessments require the version 2 contract; manual legacy proposals do not silently gain the new completeness claim.
- An explicit operator-only `audience.import_preview` copies exact preview bytes into an already-open Work case only after the existing Audience acceptance and Continuity review. It checks need revision/basis, case revision/basis, exact preview SHA, linked thread, current selected evidence, and scope. The imported Work material is proposed; its own exact-hash review and any Action grant remain mandatory.
- Repeated import of identical need revision/preview uses the existing durable event/material records and command receipts, without creating a new workflow table. No second model call is needed to import.
- Edits, deletion, policy revoke/regrant, goal changes, restart reconciliation and stale need revision block dependent preview/import/material/action. Transport catching-up remains temporary withholding, not false terminal rejection.

## Acceptance before implementation

1. Separate original publication/edit timestamps from intake; omitted dates are unknown. Existing Browser confirmation and Action static evidence hashes retain their behavior.
2. Two separate root exchanges (volunteer request and roster update) require complete version 2 context accounting. Missing, duplicate, invented, contradictory, or out-of-packet classifications/references are refused.
3. Exact quotes bind all support/counter/context dependencies. Related context edit/delete/revoke blocks immediately, before projector reconciliation, and after restart. Unrelated leaf media does not permanently poison the need.
4. The inert preview is exact, bounded and evidence scoped; SHA is computed over actual UTF-8 bytes. Proposing/capturing/restarting creates no memory acceptance, person, conversation, draft, contact permission, send, action or Work case.
5. Import requires both existing business reviews, an exact linked Work case, revisions/current basis, exact preview SHA and operator actor before receipt replay. Imported material remains proposed, repeated import is durable/idempotent, and stale/cross-partner/cross-need/cross-case import is refused.
6. UI displays all supplied context accounting, original/observed clocks and uncertainty, safely escapes text, exposes inert preview, and keeps acceptance/import/material review separate. Old proposals explicitly show missing context review rather than fabricated completeness.
7. Model runtime enforces version 2 on new captures; tools, late/stale completion, crash recovery and considered-batch no-rebilling behavior remain unchanged.
8. Run focused acceptance/runtime/UI and independent kill review; then full Node, credential isolation, build and diff checks. Use a finite real Gemini conformance check if needed, without contact/send effects. Record exact results and any unresolved quality limits here before release.

## Results

Implemented using the existing migration-12 tables and versioned JSON records. There is no database migration, generic infrastructure, provider switch, Telegram mapper change, default activation, or new send capability.

Local full gate: **1210/1210 Node tests + 15/15 Python credential-isolation tests + build + `git diff --check` PASS**. Build compiled 188 JavaScript/JSON files and 9 Python files. The new acceptance/boundary/runtime tests exercise source clocks, complete bounded context accounting, invalid quotes/references/authority fields, selected-context edit/delete/revoke/regrant/restart, unrelated backlog recovery, exact-byte preview import, both reviews, actor-before-receipt checks, stale/superseded/rejected replay, corrupt persisted proposal/material, and propagation of 31 contextual references across four sources into Continuity/Work/Action. The UI tests cover escaped previews, clocks, import guards and reading a need's older assessment outside the recent-list window.

Two explicitly finite real Hermes/Gemini conformance turns were made in isolated synthetic-source stores using the historical request/roster texts and original source clocks, plus one clearly synthetic unrelated exchange. No native monitor grants/checkpoints were copied and no Telegram transport was started. The first returned all three classifications and useful text, but was rejected by the initial duplicate requirement that its citation list enumerate the whole material basis. The design was corrected so citations are model output while the **full inherited dependency basis is computed by HARNES**. The failed receipt remains failed; it was not reset, overwritten, or automatically repurchased. A separate bounded test of the corrected contract returned `proposal_created`, all three classifications (supporting/related/unrelated), an 825-byte briefing plus suggested clarification, and explicit uncertainty about whether the request was fulfilled. It correctly distinguished publication at 07:44:32Z from intake at 17:28:03Z.

Configured and worker-reported identity: `gemini-3-flash`. Worker-reported API calls: one per turn (two total); underlying proxy/provider retries were not independently measured. First usage 5921 input / 614 output tokens; second 6046 / 737; total 11967 / 1351. Prices/cost remain **unknown**, not zero. Each conformance store retains durable attempt, run, assessment and private output files under ignored `.cache/`. Both had zero persons, private conversations, drafts, contact permissions, delivery attempts, approvals, Work links/cases/materials and Action proposals. No owner business reviews were performed for the real pilot.

## Honest remaining limits and next priority

- Context classification and preview prose remain unverified model interpretations. Complete packet accounting proves that all supplied exchanges were represented, not that the model understood them correctly. In the real check, “взрослый секундомер” was interpreted as timing equipment; it may denote a timekeeper role. The proposed clarification is useful to inspect, but that ambiguity remains a quality issue, not a verified fact. A green suite and one successful model turn do not establish recommendation usefulness.
- The bounded packet is not all channel history. Future related root posts outside the packet can be missed. A revised need starts a new scope and must be reviewed again; prior context is not automatically inherited. Its old linked memory/Work authority becomes stale. Longitudinal context selection is a later product decision.
- Exact bytes/hash and complete selected dependencies survive import, but imports remain **proposed**. Work material review and explicit local Action grant are still mandatory. External contact/publication are not implemented by this layer.
- The existing live read-only pilot independently hit a repeated Telegram `same_pts_delete_mismatch`: event 727 at 2026-10-03T17:00:23.648Z, candidate PTS 111286 versus durable checkpoint 111282 for source `telegram:channel:1206867203`. That source is safely blocked with `INTEGRITY_RECONCILIATION_REQUIRED`; other two sources were current and effects/model calls remained zero. The failed batch rolled back. Current structural fault receipts omit the two delete-ID sets/page representation, so this evidence cannot distinguish true contradiction from a legitimate overlap representation. No cursor reset, integrity bypass or automatic recovery was made. This does not arise from the proposal layer, but blocks claiming that the live channel or dependent need is current.
- **Next operational priority:** preserve bounded structural diagnostics and resolve the real Telegram overlap/reconciliation fault without weakening PTS, dedupe or recovery authority. New architecture must not obscure an unreliable source path.

Hosted exact-head CI, release SHA, mutation probe results and merge outcome are recorded in the release handoff. Production runtime/model/send defaults remain disabled.

Independent mutation probes: **4/4 killed by behavior assertions**: removing the new model-contract guard admits an invalid legacy result; removing Action context collection drops 32 selected references to one; removing assessment-output binding admits altered persisted preview bytes; removing pre-receipt currentness permits replay after material/case review. Mutants ran only in ignored scratch copies; production files and provider credentials were not used.

A full-gate rerun also exposed an existing test flake: Windows allocated loopback port 6679, which Node Fetch rejects as `bad port` before making an HTTP request. The existing server-composition kill test now uses Node's standard HTTP client for its actual loopback auth/ownership requests, retaining every response/second-owner assertion and the ephemeral-port behavior. Production server, source/outbound policy and workflow were not changed for this test issue.
