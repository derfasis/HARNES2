# Evidence-bounded Need Follow-through v1

Status: implemented release candidate; independent verification and exact-head release evidence are recorded below and in the private release handoff. Canonical base `cf65d9c3ed1a0409a2a37560257c20fd8a213437`. Separate branch `codex/evidence-bounded-need-followthrough-v1`. Native authority, caps and observer deadline are unchanged. PC shutdown remains cancelled.

## Product result

The owner opens an existing hypothesis, sees what arrived since its previous assessment, selects an immutable model profile, and authorizes exactly one focused follow-up. The partner can propose a new revision/material from currently supportable evidence. Previous acceptance, material/action approvals and contact/send permissions never transfer to the new revision. Empty output leaves resolution unknown.

This addresses two independently verified gaps: the current focused path requires the global Audience model switch, and it always requires every prior exchange to remain fresh. Synthetic clock probes showed that an expired old anchor prevents follow-up even with a new independent exchange or a fresh reply. Merely putting a profile selector on that path is insufficient.

## Records and boundaries

- Reuse existing Audience goals/exchanges/needs/assessments, immutable model profiles, runs/usage, Control Plane, scheduler fairness, no-tools Hermes and owner/Work review. No new runtime, provider client, parser, queue or generic framework; HARNES-specific authority/provenance is our custom code.
- Add `audience_followup_requests` and `audience_followup_attempts` in migration 015. Requests are explicit operator-only, immutable, one-shot authority for one need revision/basis, one displayed context fingerprint and source heads, one profile ID/hash and expiry. The attempt row is append-only and unique per request. Profile availability or ordinary attention never authorizes follow-up.
- Request → captured assessment → transactional run/admission/attempt binding → executing → durable usage/receipt → validated proposal or withheld/failed. Request revocation/expiry, source withdrawal, changed context/need/profile or lost CP ownership blocks dependent work. Consumed authority never resumes after crash or ambiguous receipt. New retry needs separately explicit new authority; no automatic retry grant.
- Preview/context fingerprint and request definition also freeze `execution_bounds` (timeout and two maximum generation requests from HARNES to its provider/proxy). A subsequent global timeout edit cannot retarget an admitted request. The no-tool runtime receives only its immutable profile fields plus these bounds; historical proof validates that whole projection. `maxApiCalls` is enforced before HTTP dispatch through installed HTTPX request hooks across newly created sync/async SDK clients. SDK retries, replacement clients and summary generation share the same cap; GET/HEAD and the pinned read-only Ollama `/api/show` metadata probe are separate from generation. Proxy-internal upstream retries/billing are not visible or attested by this count.
- Historical hypothesis memory is explicitly unverified and can be stale. Its old source IDs/reasons are history metadata; expired text is not forwarded as current source evidence. Current support consists only of currently allowed, supported, latest event versions newer than the prior assessment's source heads (legacy baseline remains explicitly unknown).
- An expired but existing supported ancestor may establish only structural lineage, never fresh support. Every necessary parent is version-bound and checked for missing/deleted/opaque/revoked/cyclic/incomplete ancestry. A fresh reply to an old anchor is admitted at event granularity only after that full lineage check. A source freshness ping or re-read of unchanged Telegram content is not a new event.
- Versioned `scope.version=2, purpose=audience_current_events_v1` binds each selected exchange's current event IDs, structural event IDs and fingerprint to current source policies. Legacy whole-exchange freshness semantics stay strict. No old basis is relabeled current. New need basis is a new projection from the exact fresh packet and requires new review.
- Pending/running follow-up binds observation heads and exact target need/context. A completed genuine receipt remains historical without invalidating itself because its own proposal changed the need revision. Subsequent need/Work currentness still checks fresh event versions/age and necessary lineage.
- Import retains history but retires requests and pending work; no authority crosses transfer. Catalogues through schema 014 remain supported. Retention is not redesigned; query/candidate work remains bounded.

## Operator contract

Service module `business/audience-followup.mjs`, `service.followup`.

- `GET /api/audience/needs/:id/followup-context` / `followup.context(needId)`: version/purpose, need ID/revision/basis, observation heads/context fingerprint, `historical_memory`, text-free historical evidence metadata, fresh `exchanges`, versioned `scope`, `available/reasons`, immutable `profile_options`, pending request/history. Loading is not a grant or provider call.
- `audience.followup_request`: exact payload `{need_id, expected_revision, expected_basis_fingerprint, expected_context_fingerprint, model_profile_id, expected_profile_hash, expires_at, reason}`. Future UTC expiry ≤7 days; reason 1–500 characters. Return `{request_id, assessment_id, executable:false, contact_permission:false, allowed_effects:[]}`. One admitted logical model turn and at most two client-side generation requests, including retries. A third request is blocked before dispatch; completion is withheld, known usage is retained, and authority stays consumed.
- `audience.followup_revoke`: `{request_id, expected_request_fingerprint, reason}`. Retires captured/running dependent assessment; child cancellation is best effort and late result is always withheld. History/usage/attempt stay retained.
- `GET /api/audience/followups/:id`: independently checked request definition, derived state, consumed attempt/run/receipt metadata; no capability or authority mutation.

Existing global model/runtime flags remain off. A fresh independent goal/need, ordinary grant, accepted Work or available credential cannot borrow this one-shot request. Financial/domain/global budgets and unknown-cost rules remain mandatory.

## Acceptance before implementation

1. Old evidence expires; a new independently current exchange or fresh reply permits a fresh context, while old text cannot be cited or appear in model evidence. Required parent deletion/opacity/revocation/missing ancestry blocks that path. The old need remains stale until a new independently supported revision is reviewed.
2. Loading context/profile or holding ordinary authority yields zero focused calls. One exact explicit request admits one selected-profile turn with global flags off; unrelated needs/goals/planes remain off.
3. Changed source/head/need/profile/authority between owner preview, admission and late application withholds output while retaining usage/consumed attempt. Frozen metadata/packet tampering fails closed; missing attempt/request records cannot downgrade to legacy.
4. Empty/invalid/failed/unknown completion, crash before dispatch, durable receipt failure, restart, explicit revoke and replay cannot re-bill the same request or resurrect pending work. A fresh retry requires separate reviewed authority.
5. Updated need is `proposed`, never automatically accepted/resolved. Old Work/material/action approvals are stale and require existing independent reviews; no person/contact/draft/send is created.
6. Fair bounded scheduler skips a broken/expired request without starving healthy ordinary or follow-up work. Source/reasoning loops and CP resource ownership remain separate.
7. Real Hermes envelope uses the validated frozen profile, no tools/business URL/run token. Transfer revokes executable authority; schema 014/older positive controls retain history safely.
8. Actual UI handlers present historical versus fresh evidence, uncertainty, exact profile/context and billing/one-shot limits. Model requests only occur after that separate confirmation.

## Verification and limits

Acceptance tests were written before implementation. Their first RED was interface absence, not semantic guard proof. Final executable tests cover fresh independent events and replies with expired structural ancestors; exact target, context, source heads, profile and runtime; source withdrawal/restoration; empty/invalid output; interrupted, unspent and consumed recovery; failed receipt persistence; missing request/attempt proof; no inherited Work/material/Action approval; actual authenticated server, UI handlers, scheduler and Hermes child envelope; and exact schema015/014 staging transfer.

An independent isolated mutation probe runs tracked kill/recovery tests: clean baseline 36/36, eight deliberately broken semantic boundaries all fail their intended assertions. These boundaries are unsupported ancestry, expiry at late apply, observation-head-only changes, exact attempt provenance, exact target need, frozen runtime projection, temporary history-only source recovery, and completion request accounting. Some mutants disable a complete boundary consisting of redundant guards; this does not claim each individual guard is independently necessary. Copied modules are restored byte-for-byte, with original/restored SHA-256 comparisons against the actual source files. No production file was mutated during the probe. Separate Python black-box checks use real HTTPX/OpenAI SDK behavior and the pinned Hermes worker against a loopback completion stub to verify the pre-network cap rather than merely asserting the envelope's number.

An initial real CLIProxy/Gemini conformance used only a retained synthetic store. It exercised a fresh reply to a two-hour-expired anchor, produced a proposed/current Russian internal briefing, and preserved an unknown resolution. Reported usage: one logical turn, one Hermes iteration, 5261 input / 955 output tokens. This initial run preceded the request-hook fix and therefore does not independently prove an HTTP-request count. Price remains UNKNOWN; the returned `gemini-3-flash` identity is a provider/proxy alias, not independent upstream-model attestation. Expired ancestor text was absent from model input. No person, conversation, draft, contact permission, delivery, task, Work/material or Action record was created. Test request and profile were revoked afterward; global runtime/Audience-model/scheduler/live-sending flags remained off. The generated wording remains inspectable, unverified model material; one conformance call does not prove longitudinal usefulness or editorial quality.

The full gate and exact-head hosted run are prerequisites to integration; final command logs and the exact release SHA are retained in `.cache/RELEASE_HANDOFF.md` and `.cache/RELEASE_EVIDENCE.json`. No native store or cap was renewed or reset. The existing native read-only observer stopped at its original finite deadline, with zero model calls and zero contact/send effects; this is unrelated to PC shutdown, which stays cancelled.

Final local release gate: **1459/1459 Node tests + 25/25 Python tests + build + diff check — PASS**. The build checked 230 JavaScript/JSON and 11 Python files. The ten new Python tests include actual OpenAI SDK retries, redirects, concurrent clients, and two real pinned-Hermes/SSE subprocess controls with external DNS/socket connections denied. The empty-response case dispatches exactly two generation requests, reports 34/0 tokens and withholds completion; the healthy control dispatches one and records 17/6 tokens.

A second separately capped real Gemini conformance used the final request-hook implementation on another synthetic store: **one actual HARNES generation HTTP request**, 5262 input / 976 output tokens, proposed/current internal material and unknown resolution. Test request/profile were revoked afterward and all effect counters were zero. Upstream proxy retries, independently served model version, actual price and real-world usefulness remain unknown. In particular, the generated hypothesis sometimes phrases a self-report as an action having occurred; the material preserves its self-report limitation, and neither wording is verified fact or accepted work. This is an owner-review quality risk, not evidence of successful completion.

The generic mechanism is the installed SDK/HTTPX transport and its [documented request hooks](https://www.python-httpx.org/advanced/event-hooks/), reviewed against the [OSS client implementation](https://github.com/encode/httpx/blob/master/httpx/_client.py). Our thin adapter adds only per-run authority counting; it does not implement a provider client, HTTP transport or general parser. The pinned Hermes revision/license and private conversation runner remain unchanged. The cap applies specifically to new follow-up authority; legacy worker paths retain their existing contracts.

### Problems found and fixed during implementation

- Legacy whole-exchange age rejected every fresh reply when its root aged. The new versioned current-event scope checks required structural versions separately and never relaxes the legacy scope.
- A global provider-readiness check also blocked an explicitly authorized scoped request. Routing and authenticated manual wake now admit that separate Audience authority; other planes still require their own readiness/authority.
- A temporary source-health loss could be flattened into a terminal stale error during captured-request reconciliation. Temporary unavailable/backlog states now wait without consuming authority, and a healthy positive control resumes the same request once.
- Aligning forged assessment and frozen-run packets could defeat simple packet equality. Historical proof now independently binds frozen source text and lineage fingerprints to canonical immutable events; a version2 need cannot downgrade to legacy output.
- Bounds previously inherited unshown mutable global settings. The request now freezes the bounded execution projection and the context confirmation detects pre-request changes.
- Failure to commit a result receipt rolled back known billing usage along with the proposed interpretation. Recovery now retains available token/cost accounting in an interrupted run, with no successful result receipt or accepted proposal.
- A history-only source on another transport could turn a temporary outage into terminal `stale` even when the fresh selected source remained healthy. Context admission and the existing general retirement loop now preserve the temporary classification and resume the same unspent request after recovery; real withdrawal still retires dependent work.
- Hermes iteration count was falsely treated as an API-request limit: hidden retries and post-budget summary generation could exceed it. The per-worker HTTPX hook counts actual generation dispatches and rejects the third before network access; successful follow-up also requires positive known accounting within its frozen cap. No upstream Hermes source was modified. Its metadata GET/HEAD and `/api/show` probes are not represented as generation. The Python tests supply valid streaming SSE responses and fence the subprocess to loopback, so failed JSON-as-SSE fixtures or hidden external metadata traffic cannot manufacture a pass.
- The first UI fixture used an invented exchange/lineage shape and hid real structural IDs. The view and fixture now use canonical scope IDs and render escaped unverified hypothesis memory separately from fresh source text.
- Several first tests were falsely specific or vacuous: a fresh independent root must not invent an old ancestor; expiry can already increment the old need revision; ordinary authority may legally fund ordinary work; a fixture transport ignores a live-reader health map. Fixtures and positive controls were corrected, without weakening production constraints. The observation-head mutation witness is tracked and uses a real durable unrelated opaque event while selected evidence remains unchanged.

This layer does not prove resolution, causal credit, audience completeness or seven-day product usefulness. New sources still require existing admission. Model text is untrusted interpretation, and a new need revision requires separate review before Work or any bounded action. If SQLite itself cannot commit either the primary receipt or recovery accounting, the attempt remains consumed and recovery requires the existing interrupted/unknown policy; no automatic provider retry is authorized.
